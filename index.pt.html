CircuitsVibe é o vitest dos circuitos. Um agente escreve uma bancada em TypeScript, roda verify, decide pelo código de saída, lê diagnósticos com códigos estáveis e localização no fonte, aplica hints verificados por simulação — e itera até ficar verde.

O loop do agente

O loop de feedback que fez os agentes de código funcionarem — agora para eletrônica.

Uma bancada é um teste: o circuito mais a especificação em forma de asserções. verify sobe a escada lint → op → tran com fail-fast; cada falha carrega um código estável, a linha do fonte e — quando você delega o dimensionamento — um hint que a plataforma já simulou.

Escreva a bancada

Componentes com pinos nomeados, tb.param para valores livres, tb.expect para a especificação.

Rode verify

O lint checa a topologia como grafo antes de qualquer solver; depois o ponto de operação DC; depois o transitório.

Leia o diagnóstico

Código estável (A301, F105), medido vs esperado, at arquivo:linha.

Aplique o hint verificado

A faixa que passa foi simulada, não chutada. --set R1=261.016 ou edite a bancada.

Verde

PASS · exit 0. Saída determinística: duas execuções dão um diff limpo, e o agente vê exatamente o que mudou.

Início rápido

Funcionando numa pasta vazia.

Nada para instalar antes — o npx baixa o pacote. init cria uma bancada e um playbook AGENTS.md; verify roda a escada; --json devolve o RunRecord completo para agentes.

led-driver.bench.tsTypeScript
import { bench, VoltageSource, Resistor, LED } from 'circuitsvibe';

export default bench('led-driver', (tb) => {
  const v1 = tb.add('V1', new VoltageSource(5));
  const r1 = tb.add('R1', new Resistor('330'));
  const d1 = tb.add('D1', new LED());
  v1.pin('+').connect(r1.pin('1'));
  r1.pin('2').connect(d1.pin('anode'));
  d1.pin('cathode').connect(tb.gnd);
  v1.pin('-').connect(tb.gnd);

  tb.param('R1', { min: '100', max: '10k', scale: 'log' }); // sizing is the platform's job
  tb.expect.op('D1.i').toBeWithin('8m', '12m');             // spec as a test
});
Por que funciona para agentes

Diagnósticos para decidir. Números para confiar.

Cada decisão de design serve a uma métrica: iterações até o verde. Menos texto para parsear, menos chutes, nenhuma mentira silenciosa.

Códigos de diagnóstico estáveis

F101…T002 são permanentes — nunca renumerados — então parsers e agentes podem depender deles. Cada um tem slug, severidade e docs via explain.

Lint antes do solver

Nós flutuantes, componentes desconectados, laços de fonte e diodos grampeados são pegos no grafo puro. singular matrix nunca chega até você.

Hints verificados por simulação

Declare tb.param('R1', …). Quando uma asserção falha, a plataforma varre a faixa, simula cada ponto e devolve o intervalo que comprovadamente passa.

Códigos de saída com significado

0 passou · 1 spec não atendida · 2 circuito inválido · 3 erro de ferramenta. O agente decide o próximo passo sem ler prosa.

Determinístico por projeto

Sem timestamps, sem cores no --json; o hash da netlist identifica o circuito. Duas execuções idênticas produzem registros byte a byte iguais.

Roda em Node e no navegador

O mesmo motor — Análise Nodal Modificada com Newton-Raphson — na CLI, num test runner e no simulador visual.

Zero dependências nativas

TypeScript puro. Rode com npx em qualquer lugar, ou leve o arquivo único circuitsvibe-standalone.mjs para um sandbox sem rede.

Um histórico de execuções

Cada execução é anexada a .circuitsvibe/runs.jsonl. log list e log show recuperam o que já foi tentado depois que o contexto se foi.
