Documentation

Everything CircuitsVibe ships today: a TypeScript bench goes through lint → DC operating point → DC sweep → AC → transient and comes back as a verdict you can branch on, with structured diagnostics, datasheet checks of real parts, mixed-signal logic, VHDL blocks, Arduino-style firmware and share links that re-run the same engine in your browser. Every example on this page is a real bench from the repository: copy it, or open it in the viewer.

Getting started#

CircuitsVibe is a circuit simulator you drive from code — vitest for circuits. You describe a circuit and its spec in a TypeScript bench; verify lints the topology, solves it with a Modified-Nodal-Analysis engine (Newton-Raphson for the nonlinear parts, event-driven logic and firmware co-simulated with the transient) and answers with a verdict, an exit code and diagnostics that carry a stable code, a source location and — where possible — a fix the platform has already simulated. The same engine runs in Node and in the browser, with zero native dependencies.

Install nothing, run in an empty folder#

terminalsh
$ npx circuitsvibe init my-circuit            # my-circuit.bench.ts + AGENTS.md
$ npx circuitsvibe verify my-circuit.bench.ts  # lint → op → dc → ac → tran, exit 0/1/2/3
$ npx circuitsvibe verify my-circuit.bench.ts --json > run.json   # the full RunRecord
$ npx circuitsvibe share my-circuit.bench.ts   # a link that opens the circuit in the viewer
  • init [name] writes <name>.bench.ts (an LED driver that passes as-is) and an AGENTS.md playbook for your coding agent (an existing AGENTS.md is never touched).
  • verify runs only the stages your bench asserts on; lint always runs first. The exit code is the verdict: 0 pass · 1 spec not met · 2 invalid circuit · 3 tooling error.
  • share prints a URL with the whole circuit in its fragment (…/app.html#c=1.…): no upload, no server. Opening it shows the schematic and re-runs the simulation in the browser.
  • The short alias cvibe accepts every command: npx cvibe verify …. Bench files need nothing installed — the CLI transpiles them itself; npm i -D circuitsvibe only adds editor types.

Offline or sandboxed agents#

When npm is out of reach, download the whole CLI as one zero-dependency file and run it with Node:

Your first bench#

This is bench/led-driver.bench.ts from the repository: a 5 V supply, a series resistor and an LED. Three ideas in twenty lines — components get stable ids ('R1'), pins have names ('anode', '+'), and the spec is an assertion on a probe. tb.param hands the resistor value to the platform: if an assertion fails, you get a simulated passing range instead of a guess.

bench/led-driver.bench.tsTypeScript
import { bench, VoltageSource, Resistor, LED } from 'circuitsvibe';

/**
 * LED driver: 5 V supply, series resistor, LED to ground.
 * The canonical "hello world" of the verification ladder — passes as written.
 */
export default bench('led-driver', (tb) => {
  const v1 = tb.add('V1', new VoltageSource(5));
  const r1 = tb.add('R1', new Resistor('330'));
  const d1 = tb.add('D1', new LED());

  v1.pin('+').connect(r1.pin('1'));
  r1.pin('2').connect(d1.pin('anode'));
  d1.pin('cathode').connect(tb.gnd);
  v1.pin('-').connect(tb.gnd);

  tb.name('led', d1.pin('anode'));

  // The platform explores this range for verified sizing hints if needed.
  tb.param('R1', { min: '100', max: '10k', scale: 'log' });

  tb.expect.op('D1.i').toBeWithin('5m', '15m'); // LED bright but safe
  tb.expect.op('led').toBeWithin(1.8, 2.6);     // sane forward voltage
});

The agent loop#

An LLM agent iterates on a circuit the way it iterates on code with a test runner. The loop below is the one in AGENTS.md; follow it exactly and branch on the exit code, never on prose.

  1. Write a bench <name>.bench.ts (start from npx circuitsvibe init <name>).
  2. Verify: npx circuitsvibe verify <name>.bench.ts --json.
  3. Branch on the exit code — see the table below.
  4. Read diagnostics, not guesses: each has code, message, at (file:line), note and fixes[]; a fix's confidence says how much to trust it. npx circuitsvibe explain <code> gives the physics.
  5. Before retrying, check history: npx circuitsvibe log list --json lists every past run (verdict, exit code, first failure, overrides). Never repeat a configuration that already failed; log show <runId> returns the full past RunRecord.
  6. Once --set values pass, write them back into the bench so the file is the truth.
  7. Share the result: after exit 0, npx circuitsvibe share <name>.bench.ts (or --share on the passing verify --json and read share.url) and give the user that link.

Exit codes#

ExitMeaningWhat to do
0all requested stages passeddone — share the link
1the circuit is valid but a spec assertion failed (A301), or a real part is over its datasheet ratings (R4xx)look for hint on the failed assertion. If hint.kind === "verified-param-range", apply it without editing code: --set R1=<hint.suggestedValue> and re-verify. No hint → change values or topology
2the circuit is invalid or unsolvable (F1xx lint, S1xx/S2xx solver, digital/VHDL errors)fix the structure at diagnostics[].at before touching values
3tooling error: the bench threw or failed to compile, the command was misused, an AC bench has no usable stimulus (T003/T004), a .model card or circuit document is invalidread stderr / diagnostics[]; fix the bench code or the invocation

The ladder is fail-fast: lint runs on the connection graph before any solver; when a stage fails, later stages are reported as skipped with a reason, so there is never a question of which of several errors is the root cause. firstFailure in the RunRecord names the assertion id or code that decided the verdict.

  • passingRange covers only the longest contiguous run of passing samples; the exact simulated values are in passingSamples. With real parts, the hint also keeps every datasheet rating within limits.
  • No hint in the record means no value in the declared range satisfies the spec: change the topology, not the number. --no-hints skips the sweep when you only want the verdict.

Fix confidence#

verified

The platform simulated the fix and it passes all of the stage's assertions (and ratings). Apply it directly.

mechanical

A deterministic transformation — not simulated, but no judgment required.

suggested

A heuristic. Reason before applying.

Two invariants hold: a fix never references a flag or capability that does not exist, and an unsimulated number is never emitted without the suggested label.

Determinism. Output contains no timestamps and no terminal colors; the netlist hash identifies the circuit, and matrix unknowns are ordered by component id and net name, so the same netlist gives the same numbers whatever the declaration order. Two identical runs produce byte-identical records — the diff between two agent iterations shows only what actually changed.

Bench API#

A bench file default-exports bench(name, build). The build function is lazy: it runs at elaboration time, possibly several times with different parameter overrides (--set, hint sweeps), so keep it pure — build the circuit from its arguments and nothing else. Everything is imported from 'circuitsvibe'.

cheat sheetTypeScript
import { bench, VoltageSource, Resistor, Capacitor, LED } from 'circuitsvibe';

export default bench('rc-led', (tb) => {
  const v1 = tb.add('V1', new VoltageSource(5));     // id → stable name in every diagnostic
  const r1 = tb.add('R1', new Resistor('330'));      // always use the RETURNED instance
  const d1 = tb.add('D1', new LED());
  v1.pin('+').connect(r1.pin('1'));
  r1.pin('2').connect(d1.pin('anode'));
  d1.pin('cathode').connect(tb.gnd);                 // tb.gnd is the ground net
  v1.pin('-').connect(tb.gnd);

  tb.name('led', d1.pin('anode'));                   // name a net → probe 'led'
  tb.param('R1', { min: '100', max: '10k', scale: 'log' });  // free parameter for hints

  tb.expect.op('D1.i').toBeWithin('8m', '12m');      // DC operating point
  tb.expect.op('led').toBeWithin(1.8, 2.6);
  tb.expect.dc({ source: 'V1', from: 0, to: 5, points: 51 })   // DC sweep of V1
    .probe('D1.i').toBeMonotonic('increasing')
    .at('3').toBeBelow('5m');
  tb.expect.tran({ tstop: '5m', dt: '10u' })         // transient (adaptive steps)
    .probe('D1.i').toNeverExceed('25m');
});
bench(name: string, build: (tb) => void)

Declares a testbench. name appears in every report, RunRecord and circuit document.

tb.add(id: string, component: T): T

Registers a component under a stable id — a letter first, then letters, digits or underscore ('R1', 'U2', 'VCC'), unique in the bench. The id is how probes, diagnostics, --set and the viewer refer to it.

Always use the returned value and register before connecting. When an override is active, add returns a rebuilt instance; pins connected before tb.add are refused, and a part wired into the circuit but never registered is an elaboration error (exit 3).

pin.connect(otherPin: Pin) · component.pin(name | number)

Wires two pins into the same net. Pin names are the component's ('1'/'2', '+'/'-', 'anode', 'c'/'b'/'e', 'inp'/'inn', …); logic ICs also accept datasheet pin numbers (u1.pin(14)).

tb.gnd: Pin

The ground pin. Every net needs a DC path to it (F101 otherwise).

tb.name(netName: string, pin: Pin)

Names the electrical net containing pin so it can be probed in any stage (tb.expect.op('out'), .probe('out'), tb.expect.logic('out')). gnd and the auto-generated n<digits> are reserved; automatic nets are deliberately not addressable, so probes stay stable across edits.

tb.param(id, { min, max, scale?: 'lin' | 'log' })

Declares a free parameter over a component's main value (a source's DC value). min < max; 'log' requires min > 0. When an op assertion or rating fails, the platform sweeps the range, simulates every sample and attaches the passing range as a verified hint. Microcontrollers cannot be targeted.

tb.ratings({ derate?, pd?: 'average' | 'peak', ignore?: string[] } | false)

Datasheet checks of real parts: { derate: 0.8 } keeps a 20 % margin, { pd: 'peak' } compares instantaneous instead of window-average power in the transient, { ignore: ['Q1'] } skips parts, false disables the checks. See Datasheet ratings.

tb.expect.op(probe) · dc(cfg) · ac(cfg) · tran(cfg) · logic(probe, cfg?) · serial(mcuId, cfg?)

The spec as a test — one call per analysis. See Sources & analyses and the Assertions reference.

Values and units#

Anywhere a value is expected you can pass a number or a string with an engineering suffix: '4.7k', '10m', '2u', '1M', '100n', '1e-6'. A trailing unit (V A F H s Hz ohm Ω) is allowed and ignored: '10uF', '5V'.

m ≠ M. m is milli (10⁻³) and M is mega (10⁶): '10m' is 10 mΩ / 10 mA / 10 ms; '1M' is 1 MΩ or 1 MHz.
Bench files are CommonJS under the hood: no top-level await, no import.meta. Relative imports of other .ts/.js/.json files work, and .vhd files import as VHDL source.

Sources & analyses#

Four analyses, each declared by the assertions that need it: op (DC operating point), dc (a sweep of a source or a component value), ac (small-signal frequency response around the operating point) and tran (adaptive transient). Lint always runs first; a bench that asserts only on op runs only lint and op.

Sources#

VoltageSource and CurrentSource take a value, or an options object with at most one waveform. All values accept units.

sourcesTypeScript
new VoltageSource(5)                                                   // DC
new VoltageSource({ dc: 2.5, ac: 1 })                                  // bias + AC stimulus (1 V, 0°)
new VoltageSource({ ac: { mag: 1, phase: 90 } })                       // AC only (dc 0)
new VoltageSource({ sin: { offset: 0, amplitude: 1, freq: '1k', delay: '1m', damping: 0, phase: 0 } })
new VoltageSource({ pulse: { v1: 0, v2: 5, td: '1m', tr: '1u', tf: '1u', pw: '2m', per: '5m' } })
new VoltageSource({ pwl: { points: [[0, 0], ['1m', 5], ['3m', 5], ['4m', 0]], repeat: false } })
new VoltageSource({ pwm: { low: 0, high: 5, freq: '10k', duty: '25%', rise: '100n', fall: '100n' } })
new CurrentSource('1m')                                                // same options; pushes current out of '+'
  • dc (used by op and the DC sweep) defaults to the waveform's value at t = 0.
  • PULSE: v1 → after td rises in tr to v2, holds pw, falls in tf, repeats every per (omit per for one pulse). tr/tf 0 = ideal edge. SIN phase is in degrees.
  • PWM duty is the fraction of the period above the 50 % level (0 < duty < 1; '25%' works).
  • ac is the small-signal stimulus for the AC stage; it does not affect op or tran. A bench with AC assertions and no ac source is T003.

op — DC operating point#

MNA with Newton-Raphson for nonlinear parts (pn-junction limiting). When plain Newton fails the solver retries with gmin stepping, then source stepping; when an aid rescues the solve the stage passes and stages.op.solver.aids says which one. Capacitors are open, inductors are 0 V shorts, logic ICs settle to a static state (an oscillator reports D514 as a warning), microcontrollers are in reset (pins high-Z).

op assertionsTypeScript
tb.expect.op('D1.i').toBeWithin('8m', '12m');   // min ≤ measured ≤ max
tb.expect.op('out').toBeCloseTo(3.3, 0.1);      // |measured − value| ≤ tol (absolute)
tb.expect.op('Q1.vce').toBeAbove(1.5);          // measured > value
tb.expect.op('U1.1Y').toBeBelow(0.4);           // an IC pin voltage

dc — DC sweep#

Sweeps a source's DC value (source) or a component value (param) from from to to in points steps (default 51) or by step, solving the operating point at every point warm-started from the previous one (this is what lets a Schmitt trigger show its hysteresis when swept up and then down). Measurements interpolate linearly between swept points.

dc assertionsTypeScript
tb.expect.dc({ source: 'VIN', from: 8, to: 15, points: 29 })   // or { param: 'R1', from, to, step }
  .probe('out')
  .at(12).toBeCloseTo(5.1, 0.2)            // value at a sweep point
  .slopeAt(12).toBeBelow(0.01)             // d out / d VIN
  .toBeMonotonic('increasing')             // over the whole sweep
  .toCross(2.5).between(2.7, 2.8);         // first crossing of a level, in sweep units

npx circuitsvibe sweep x.bench.ts --source V1 --from 0 --to 5 --probe out prints the same sweep as a table (or --json) without assertions.

ac — small-signal frequency response#

The circuit is linearised at the operating point and solved with complex MNA over a logarithmic sweep (from, to, pointsPerDecade). Gain definition: H(f) = probe phasor / stimulus phasor — the single source with ac — or probe / ref when .probe(p, { ref }) is given (required when several sources have ac, else T004). Gains are in dB (20·log₁₀|H|), phases in degrees (unwrapped), frequencies in Hz. A saturated op-amp output has no gain in AC.

ac assertionsTypeScript
const ac = tb.expect.ac({ from: '10', to: '10M', pointsPerDecade: 20 }).probe('out');
ac.gainAt('1k').toBeWithin(19.9, 20.1);     // dB
ac.phaseAt('100k').toBeWithin(-46, -44);    // degrees
ac.bandwidth3dB().toBeWithin('98k', '102k'); // Hz, measured from the sweep's peak gain
ac.unityGainFrequency().toBeAbove('1M');    // Hz
ac.phaseMargin().toBeAbove(45);             // 180° + phase(H) at unity gain — probe a loop gain

bandwidth3dB is the upper −3 dB frequency for a low-pass and f_high − f_low for a band-pass. A measurement that cannot be made (no −3 dB point in the sweep, no unity-gain crossing) fails with a note and no measured value — the platform never invents a number.

Example — RC low-pass Bode plot

A 1 kΩ / 1 µF low-pass (fc = 159 Hz) with a 1 V bias and the AC stimulus on the same source. The assertions pin the −3 dB point, the −45° phase and the −20 dB/decade slope.

bench/examples/rc-lowpass-bode.bench.tsTypeScript
import { bench, VoltageSource, Resistor, Capacitor } from 'circuitsvibe';

/**
 * First-order RC low-pass, R = 1 kΩ, C = 1 µF: fc = 1/(2π·RC) = 159.15 Hz.
 * The source carries a 1 V DC bias (the operating point) and the AC stimulus
 * (`ac: 1`) the Bode measurements are referenced to: −3 dB and −45° at fc,
 * −20 dB per decade above it.
 */
export default bench('rc-lowpass-bode', (tb) => {
  const vin = tb.add('VIN', new VoltageSource({ dc: 1, ac: 1 }));
  const r1 = tb.add('R1', new Resistor('1k'));
  const c1 = tb.add('C1', new Capacitor('1u'));

  vin.pin('+').connect(r1.pin('1'));
  r1.pin('2').connect(c1.pin('1'));
  c1.pin('2').connect(tb.gnd);
  vin.pin('-').connect(tb.gnd);
  tb.name('out', c1.pin('1'));

  tb.expect.op('out').toBeCloseTo(1, 1e-6);                 // the capacitor is open at DC

  const ac = tb.expect.ac({ from: '1', to: '100k', pointsPerDecade: 20 }).probe('out');
  ac.bandwidth3dB().toBeWithin('155', '163');               // fc = 159.15 Hz
  ac.gainAt('159.15').toBeWithin(-3.1, -2.9);               // −3.01 dB at fc
  ac.phaseAt('159.15').toBeWithin(-46, -44);                // −45° at fc
  ac.gainAt('1.5915k').toBeWithin(-20.5, -19.5);            // one decade up: −20 dB
  ac.gainAt('1').toBeWithin(-0.01, 0.01);                   // flat pass-band
});

tran — adaptive transient#

tb.expect.tran({ tstop, dt?, maxStep?, minStep?, method?, ic?, reltol? }) declares a transient run; .probe(p) selects a signal and can be chained to assert on several signals of the same run, .logic(p) and .serial(mcu) attach logic and firmware assertions to it.

OptionMeaning
tstopend of the window (seconds).
dtthe initial step and the step ceiling. Without dt or maxStep: initial tstop/1000, ceiling tstop/50.
maxStepoverrides the ceiling, letting the stepper stride through quiet stretches (typical with logic ICs and MCUs: { tstop: '2.2', maxStep: '10m' }).
minStepbelow it the run stops with S203 (default maxStep·1e-9).
method'trap' (default; Backward Euler right after t = 0 and every source corner) or 'be'.
ic'zero' (default — capacitors at 0 V, inductors at 0 A at t = 0: a DC source acts as a step) or 'op' (start from the DC operating point, e.g. ripple around a bias).
reltoltruncation-error tolerance of the adaptive stepper (default 1e-4).
  • Steps are adaptive (local-truncation-error control) and land exactly on every PULSE/PWL/PWM corner, logic event, output ramp corner and firmware wake time; the step is cut back to the crossing of an IC input threshold or an interrupt pin (within 1 ns). On a Newton failure the step is cut (by 8, retried with BE) before S202.
  • Samples are non-uniform and every measurement interpolates. A coarse dt on a fast circuit is fine (the stepper shrinks near edges), but output samples are only as dense as the steps actually taken.
  • Logic ICs, primitives, VHDL blocks and microcontrollers are co-simulated with the analog transient (see Logic ICs, VHDL, Microcontrollers).
tran assertionsTypeScript
const run = tb.expect.tran({ tstop: '6m', dt: '10u' });
run.probe('C1.v')
  .toSettleWithin({ target: 5, tol: 0.05, by: '4m' })  // inside 5 V ± 5 % (fraction!) from 4 ms on
  .toNeverExceed(5.5)                                  // no overshoot above 5.5 V
  .toEndCloseTo(5, 0.1)                                // last sample within 0.1 V (absolute)
  .probe('R1.i')
  .toStayBelow('6m', { from: '1m' })                   // after 1 ms, current < 6 mA
  .probe('out')
  .toRippleBelow('50m', { from: '3m' });               // peak-to-peak ripple after 3 ms
run.logic('U1.1Y').toHaveFrequency('1k', 0.01, { from: '1m' });   // same run, logic signal
Tolerance semantics. toSettleWithin tol is a fraction of the target; toBeCloseTo / toEndCloseTo tol is absolute; toHaveFrequency tol is a fraction; toHaveDutyCycle tol is absolute duty.

Custom components#

defineComponent creates a component type from a definition object. The part stamps itself into the MNA matrix through a small context and runs in the same engine as the built-ins. Give it an ac(ctx) stamp if it is used in an AC analysis (S204 otherwise) and use ctx.stampCapacitance(a, b, C) for internal capacitors so they are integrated like built-ins.

defineComponentTypeScript
import { defineComponent } from 'circuitsvibe';

const MyResistor = defineComponent({
  name: 'MyResistor',
  pins: ['a', 'b'],
  params: { R: { default: 1000, unit: 'Ω' } },
  stamp(ctx) {
    ctx.stampResistance('a', 'b', ctx.params.R);
  },

defineComponent({ name, pins, params?, stamp, ac?, setup?, onStep?, nonlinear? })

Returns a constructor: new MyPart({ paramName: value }). params maps a name to { default, unit? }; the numeric params become part of the canonical netlist, so two electrically different custom parts never share a hash.

Custom parts are code. They have no sweepable scalar (tb.param / --set do not apply), and a bench containing one cannot be exported or shared (T013): the circuit document carries only built-in types.

Datasheet ratings (real parts)#

After op, dc and tran every Part() semiconductor is checked against its absolute maximum ratings — R401 voltage (Vceo, Vcbo, Vebo, Vds, ±Vgs, VR/VRRM) · R402 continuous current (IcMax, IbMax, Id25, IF/IFAV) · R403 pulsed current (IcPeak, IdPulsed, IFP, IFSM; tran) · R404 power (Pd). Results land in stages.<stage>.ratings[], separate from your assertions (passing checks are listed too, with utilization and margin); a violation fails the stage with exit 1 — valid circuit, over-stressed part — with confidence: "verified" and the datasheet citation.

  • What is compared: op = the value; dc = the peak over the sweep (with its x); tran = the instantaneous peak for voltages and for currents without a pulsed rating; the window average for continuous currents that also have a pulsed rating (the peak goes to R403) and for Pd (tb.ratings({ pd: 'peak' }) to compare the peak instead).
  • tb.ratings({ derate: 0.8 }) keeps a 20 % margin; { ignore: ['Q1'] } skips a part; tb.ratings(false) disables the checks. With tb.param, the verified hint keeps every rating in range too.
  • Ratings run after mixed-signal transients as well: a 74HC04 driving a Part('2N3904') reports stages.tran.logic[] and stages.tran.ratings[] together. Logic ICs are not R40x-rated — an IC output over its own limit is D511.
  • A model marked ESTIMATED in npx circuitsvibe catalog <id> is a fit from datasheet curves: its numbers can be off (2N7000 Rds(on) at 4.5 V: 2.9 Ω vs 1.8 Ω typical). Pd of TO-220 parts (IRLZ44N 110 W) is rated with the case at 25 °C — derate when there is no heatsink. Junction temperature is not simulated.

Example — LM393 Schmitt trigger

A real LM393 with a pull-up and a feedback resistor from out to inp: the hysteresis comes from the resistors alone. Two DC sweeps of the input — up, then down — find the two thresholds with toCross.

bench/examples/lm393-schmitt-trigger.bench.tsTypeScript
import { bench, VoltageSource, Resistor, Part } from 'circuitsvibe';

/**
 * Non-inverting Schmitt trigger with an LM393 on 5 V: the input reaches 'inp'
 * through R1 (10 kΩ), the open-collector output is pulled up by RP (10 kΩ)
 * and fed back to 'inp' through RF (100 kΩ); a 10k/10k divider puts the
 * 2.5 V reference on 'inn'. The hysteresis is set by the resistors alone:
 *   output high (5 V): V(inp) = (10·Vin + 5)/11 → falls below 2.5 V at Vin ≈ 2.25 V
 *   output low (≈ 0 V): V(inp) = 10·Vin/11      → rises above 2.5 V at Vin ≈ 2.75 V
 * Two DC sweeps of the 0–3.3 V input (up, then down) find both thresholds.
 */
export default bench('lm393-schmitt-trigger', (tb) => {
  const u1 = tb.add('U1', Part('LM393'));
  const vcc = tb.add('VCC', new VoltageSource(5));
  const vin = tb.add('VIN', new VoltageSource(0));
  const r1 = tb.add('R1', new Resistor('10k'));
  const rf = tb.add('RF', new Resistor('100k'));
  const rp = tb.add('RP', new Resistor('10k'));
  const ra = tb.add('RA', new Resistor('10k'));
  const rb = tb.add('RB', new Resistor('10k'));

  vcc.pin('-').connect(tb.gnd);
  vin.pin('-').connect(tb.gnd);
  vcc.pin('+').connect(u1.pin('v+'));                  // single supply: v- on gnd
  u1.pin('v-').connect(tb.gnd);

  vin.pin('+').connect(r1.pin('1'));                   // input → R1 → inp
  r1.pin('2').connect(u1.pin('inp'));
  rf.pin('1').connect(u1.pin('out'));                  // positive feedback: out → RF → inp
  rf.pin('2').connect(u1.pin('inp'));
  rp.pin('1').connect(vcc.pin('+'));                   // open collector needs the pull-up
  rp.pin('2').connect(u1.pin('out'));
  ra.pin('1').connect(vcc.pin('+'));                   // 2.5 V reference on inn
  ra.pin('2').connect(u1.pin('inn'));
  rb.pin('1').connect(u1.pin('inn'));
  rb.pin('2').connect(tb.gnd);
  tb.name('out', u1.pin('out'));

  tb.expect.op('out').toBeBelow(0.1);                  // Vin = 0 → output low

    .at(2.5).toBeBelow(0.1);                           // still low at the plain-comparator point

    .at(2.5).toBeAbove(4.5);                           // still high on the way down (≈ 4.8 V: RP loaded by RF + R1)

'worst' uses the max tpd and Rout; clamp: false removes the input protection diodes. npx circuitsvibe catalog 74HC14 prints the pinout with numbers, the levels, Rout and tpd per VCC, and the citations.
  • Every logic level is referenced to the IC's own VCC/GND pins and scales with them: 74HC at 5 V VIL 1.5 V / VIH 3.5 V, at 2 V 0.5 V / 1.5 V. A rising input is recognised at VIH, a falling one at VIL; 74HC14 and the CD4017 CLOCK pin use VT+/VT− (Schmitt). A non-Schmitt input dwelling between VIL and VIH longer than the datasheet's max transition time is D508 — a slow RC edge belongs on a 74HC14.
  • Outputs are a pull-up/pull-down resistance pair (Rout from the datasheet VOH/VOL rows, interpolated over VCC) with a short ramp, so a logic output drives an LED, a transistor base or an RC node and the supply pin carries the load current. Delays are the datasheet tpd at the IC's supply (50 pF test load de-embedded). An output over its absolute maximum current is D511 (74HC: 25 mA — an LED still needs its resistor).
  • Supplies: 74HC 2–6 V, 74HCT 4.5–5.5 V (D509 at 3.3 V), CD4000B 3–18 V, NE555 4.5–16 V. An IC below half its minimum supply is unpowered — outputs high-Z (D510); a brown-out in the transient latches it off.
  • Lint: F135 VCC/GND pin unconnected · F136 two logic outputs on one analog net · F137 logic input floating (warning for an unused gate — tie it to a rail) · F138 output tied to ground / a rail / a source · F130–F134 floating input, multiple drivers, shorted outputs, zero-delay loop, undriven clock on pure-digital nets.

NE555#

Pins GND TRIG OUT RESET CONT THRES DISCH VCC (1–8). Modelled as comparators at CONT (internal 5k/5k/5k divider, 2/3 VCC) and CONT/2, an SR latch, the discharge transistor (Ron from the datasheet saturation rows), RESET (active low — tie it to VCC) and the totem-pole output (high = VCC − 0.9 V − 8 Ω·I). Astable f ≈ 1.44/((R1 + 2R2)·C), monostable T ≈ 1.1·R·C; the tests hold both within 2 %. With a small R1 the discharge node sits at VCC·Ron/(R1 + Ron) and the period grows a few percent. Oscillators have no DC state: the op stage reports D514 (warning) — assert on them in tran / logic, and measure frequencies with { from } past the start-up (the first 555 period is longer).

Primitives and families#

And Or Nand Nor Xor Xnor Not Buf TriBuf Mux DFF JKFF DLatch Counter ShiftRegister Clock Stimulus Const Pull — options and pins as in npx circuitsvibe catalog (gates take { inputs }, delay default 1 ns; Clock({ freq | period, duty, start }); Const(0 | 1 | 'X' | 'Z'); Stimulus for scripted waveforms). A net whose pins all belong to primitives is pure-digital: only the event engine sees it, and a bench with no analog part at all is simulated by the digital engine alone. Where a primitive pin touches an analog net it is bridged with the levels of { family: 'HC' | 'HCT' | 'CD4000', vcc: 5 } (reference parts 74HC04 / 74HCT04 / CD4011) at an ideal vcc against ground.

VHDL blocks#

VhdlBlock puts a VHDL entity on the logic engine as a bench component. Import the .vhd file (the CLI loads the text; .vhdl works too), and every port bit becomes a pin: std_logic and boolean ports by name ('clk'), vectors 'q[i]' per VHDL index ('q(0)' is accepted), integer/enum ports 'n[k]' per encoding bit, LSB 0.

VhdlBlockTypeScript
import { bench, VhdlBlock, VoltageSource, Resistor, LED } from 'circuitsvibe';
import counter from './counter.vhd';                 // the CLI loads the text (also .vhdl)

const u2 = tb.add('U2', new VhdlBlock({
  source: counter,          // one import, several, or inline VHDL text
  entity: 'counter',        // default: the only top-level entity
  architecture: 'rtl',      // default: the last one compiled
  generics: { N: 4 },       // integers, booleans, time ('10 ns'), std_logic '1', vectors "0101"
  family: 'HC',             // 'HC' (default) | 'HCT' | 'CD4000' — bridge levels on analog nets
  vcc: 5,                   // ideal supply of the bridge (default 5 V); no supply pins
}));
u2.pin('clk'); u2.pin('rst'); u2.pin('q[0]');        // pins = port bits
  • A VHDL block behaves like a logic primitive: on pure-digital nets (to Clock, Not, DFF, other VHDL blocks…) it runs on the event engine alone; a pin on an analog net is bridged with the family levels at the ideal vcc against ground. Outputs are 3-state ('Z' releases the pin); inout ports only on pure-digital nets. VHDL processes have zero delay unless you write after (inertial).
  • An input port left completely unconnected keeps its VHDL default (en : in std_logic := '1'); one without a default is an undriven net (F130).
  • Diagnostics V701–V749 (syntax, types, unsupported constructs) come out of the lint stage with the .vhd file:line:col (inline text: <bench line> (vhdl line:col)); V750–V755 fire at run time with the time and the VHDL line and never stop the simulation. Fixes are mechanical or suggested, never verified.
  • Integers do not wrap: leaving a subtype range is V751 and the assignment is skipped — count with unsigned vectors. The .vhd text travels in circuit documents and share links.

Example — 4-bit counter driving LEDs

A generic N-bit counter clocked by a 1 kHz PULSE source drives four LEDs; en is left open and takes its VHDL default. q[0] toggles at 500 Hz, q[3] at 62.5 Hz.

bench/vhdl/counter.vhdVHDL
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

-- N-bit up counter with synchronous reset and enable; wraps modulo 2**N.
entity counter is
  generic (N : positive := 4);
  port (
    clk : in  std_logic;
    rst : in  std_logic;          -- synchronous, active high
    en  : in  std_logic := '1';   -- count enable (defaults to always on)
    q   : out unsigned(N-1 downto 0)
  );
end entity counter;

architecture rtl of counter is
  signal count : unsigned(N-1 downto 0) := (others => '0');
begin
  process (clk)
  begin
    if rising_edge(clk) then
      if rst = '1' then
        count <= (others => '0');
      elsif en = '1' then
        count <= count + 1;
      end if;
    end if;
  end process;

  q <= count;
end architecture rtl;

Example — VHDL PWM into an RC filter

A PWM generator with generics PERIOD = 10 and DUTY = 3, clocked by a 100 kHz Clock primitive on a pure-digital net; its output bit meets an analog RC filter that averages the 10 kHz, 30 % wave to 1.5 V.

bench/vhdl/pwm.vhdVHDL
library ieee;
use ieee.std_logic_1164.all;

-- PWM generator: pwm_out is high for DUTY of every PERIOD clock cycles.
entity pwm is
  generic (
    PERIOD : positive := 10;
    DUTY   : natural  := 3
  );
  port (
    clk, rst : in  std_logic;
    pwm_out  : out std_logic
  );
end entity pwm;

architecture rtl of pwm is
  signal cnt : natural range 0 to PERIOD - 1 := 0;
begin
  process (clk)
  begin
    if rising_edge(clk) then
      if rst = '1' or cnt = PERIOD - 1 then
        cnt <= 0;
      else
        cnt <= cnt + 1;
      end if;
    end if;
  end process;

  pwm_out <= '1' when cnt < DUTY else '0';
end architecture rtl;

Firmware rules#

app.fw.tsTypeScript
import { pinMode, digitalWrite, digitalRead, analogRead, analogWrite, delay, millis,
         attachInterrupt, digitalPinToInterrupt, Serial,
         INPUT, OUTPUT, INPUT_PULLUP, HIGH, LOW, FALLING, LED_BUILTIN, A0 } from 'circuitsvibe/arduino';

let presses = 0;
function onPress() { presses++; }                 // ISR: a plain sync function, no delay() inside (M607)

export async function setup() {
  Serial.begin(9600);
  pinMode(LED_BUILTIN, OUTPUT);
  pinMode(2, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(2), onPress, FALLING);   // Uno: D2, D3
  Serial.println('ready');
}

export async function loop() {
  const code = analogRead(A0);                    // 10-bit on AVR: floor(Vin·1024/Vref)
  analogWrite(9, code >> 2);                      // PWM: real edges at the pin's timer frequency
  digitalWrite(LED_BUILTIN, presses % 2);
  Serial.println(`code=${code} presses=${presses} t=${millis()}`);
  await delay(100);                               // EVERY wait is awaited — zero time between awaits
}
  • export async function setup() and export async function loop(); import only from 'circuitsvibe/arduino' and relative files. The lint and the runtime enforce each rule below with a diagnostic — nothing can hang the simulator.
  • Every wait is await delay(ms) / await delayMicroseconds(us). Code between two awaits takes zero simulated time. A delay() without await is F140 / M605; a polling loop that never awaits is F142 / M602; Date, setTimeout, Math.random are F147 (use millis(), random()). A helper that waits must be async and awaited; a loop() that returns without awaiting is charged 10 µs (M604, once).
  • Interrupts: attachInterrupt(digitalPinToInterrupt(2), handler, RISING | FALLING | CHANGE) — passing the pin number instead is F145. The handler is a plain (sync) function and runs at the analog threshold crossing (edge time within 1 ns); delay() inside it is M607.
  • API: pinMode (INPUT, OUTPUT, INPUT_PULLUP), digitalWrite/Read, analogRead (10-bit on AVR, Vref = the simulated VCC, or analogReference(INTERNAL) 1.1 V / EXTERNAL = AREF), analogWrite (Uno D3 D9 D10 D11 at 490.196 Hz, D5 D6 at 976.5625 Hz), tone/noTone, millis/micros, Serial.begin/print/println, Timer1, random/randomSeed, map, constrain. Not available (F146): pulseIn, shiftOut, Wire/I2C, SPI, EEPROM, Wi-Fi.

Pin model, power and ratings#

  • OUTPUT = a push-pull stage from the MCU's own VCC/GND pins with Rout from the datasheet VOH/VOL rows (Uno at 5 V: 40 Ω high, 45 Ω low — guaranteed worst case), 10 ns edges. INPUT_PULLUP = the internal resistor (Uno 35 kΩ nominal). Inputs switch at VIH rising / VIL falling (0.6/0.3·VCC on AVR); ESD clamp diodes to the rails on every pin. PWM is real edges by default; { pwm: 'average' } gives the duty-cycle average without edges — faster for RC filters.
  • Co-simulation: every firmware wake time (delay end, PWM edge, Timer1 tick) is a transient breakpoint; an attachInterrupt pin cuts the step at its threshold crossing; the firmware reads the accepted solution at its own time.
  • Power: at the operating point the MCU is in reset (all pins high-Z) — assert MCU behaviour in tran/logic/serial, not op. It must be powered at t = 0 (else M622, it never starts); a supply that later falls below the reset threshold (Uno brown-out 2.7 V) latches it in reset (M622; restart not modelled); outside 4.5–5.5 V (Uno at 16 MHz) M623 (warning; error above the 6 V absolute maximum). Supply pins must be wired (F139).
  • Ratings in stages.tran.ratings[] (exit 1 like R40x): R410 a pin over its absolute maximum (Uno 40 mA — an LED without a resistor draws ≈ 70 mA), R412 a port group (Uno: D5–D13 source/sink 100 mA together), R413 VCC/GND or total current; R411 (warning) a pin over the 20 mA VOH/VOL test current. tb.ratings({ derate, ignore: ['U1'] }) applies.
  • Probes: a logic probe on an MCU pin ('U1.D13') is the driven level while the pin is an OUTPUT and the input-buffer level otherwise; a voltage probe ('U1.D9') is the pin voltage.
  • Diagnostics: M601 (firmware exception) … M623 carry the firmware file:line in at (e.g. bench/mcu/blink.fw.ts:12) and the simulation time; F14x and M608 (load/compile errors) come from the lint stage, before anything is simulated.
  • Share links: the firmware file and its relative imports travel in the circuit document (sources[]), so share, open and verify x.circuit.json reproduce the run. Inline { setup, loop } functions (library use) cannot be exported (T013). --set / tb.param cannot target an MCU.

What is not modelled#

Instruction timing (zero time between awaits), ISRs preempting a running slice (they run at the next yield, same timestamp), UART timing and serial input from the bench (Serial.read() sees nothing), ADC conversion time, sleep modes / watchdog, the core's supply current, delayed power-up and restart after a brown-out, pulseIn / shiftOut / I2C / SPI / EEPROM / Wi-Fi; millis() is exact (no 1.024 ms AVR jitter) and PWM periods are timer-aligned from t = 0. Library use: MCU firmware is async, so call await runLadderAsync(bench) (the CLI does).

Example — button interrupt and Serial

A 2N7000 pulls D2 (INPUT_PULLUP) low five times; the firmware counts FALLING-edge interrupts and reports the count on Serial while D13 mirrors its parity.

bench/mcu/button-counter.fw.tsTypeScript
// Counts button presses on D2 (INPUT_PULLUP, interrupt on the FALLING edge) and
// prints the count from loop(); D13 mirrors the count's parity.
import { pinMode, digitalWrite, attachInterrupt, digitalPinToInterrupt, delay, Serial, INPUT_PULLUP, OUTPUT, FALLING } from 'circuitsvibe/arduino';

let presses = 0;
let reported = 0;

function onPress() {
  presses++;
}

export async function setup() {
  Serial.begin(9600);
  pinMode(2, INPUT_PULLUP);
  pinMode(13, OUTPUT);
  attachInterrupt(digitalPinToInterrupt(2), onPress, FALLING);
}

export async function loop() {
  if (presses !== reported) {
    reported = presses;
    digitalWrite(13, reported % 2);
    Serial.println(`presses=${reported}`);
  }
  await delay(5);
}

 * of 20 ms every 60 ms. The firmware counts FALLING-edge interrupts and prints
 * the count. The PULSE edges are clean (1 µs), so there is no contact bounce
 * and the firmware needs no debounce: the count equals the number of presses.
 */

  const m1 = tb.add('M1', Part('2N7000'));

  u1.pin('5V').connect(v5.pin('+'));
  u1.pin('GND').connect(tb.gnd);

  rg.pin('2').connect(m1.pin('g'));

  m1.pin('d').connect(u1.pin('D2'));
  tb.name('button', u1.pin('D2'));

  run.logic('U1.D2').toToggle({ edge: 'falling', count: 5 });
  run.serial('U1').toContain('presses=5\r\n').toHaveLines(5).toNotContain('presses=6');
  run.logic('U1.D13').toBe(1).at('0.3'); // odd count

Share links & the circuit document#

A bench can be turned into a circuit document: plain JSON (circuitsvibe-circuit/1) with the components, wiring, free parameters, assertions with their analysis configs, optional metadata and embedded source files (firmware, VHDL). It is the language-neutral contract between every producer and consumer of circuits: the TypeScript bench writes it, verify x.circuit.json simulates it exactly like the bench, and share links carry it compressed in the URL fragment.

$ npx circuitsvibe export led-driver.bench.ts -o led-driver.circuit.json   # [--set R1=270] [--title …]
$ npx circuitsvibe verify led-driver.circuit.json --json   # same RunRecord and exit code as the bench

$ npx circuitsvibe share led-driver.bench.ts --json        # { "url", "bytes", "warnings" }

$ npx circuitsvibe open "https://circuitsvibe.com/app.html#c=1.…" -o back.circuit.json   # link → document

The viewer#

Opening a share link at circuitsvibe.com draws the schematic automatically, re-runs the same engine in the browser — same verdict, exit code and netlist hash as the CLI run — and shows the assertions, diagnostics, ratings, scope waveforms, Bode and DC-sweep plots, the logic analyzer and the serial output, with a live current animation. Every "Open in viewer" button on this page is such a link. The document lives in the fragment, which browsers never send to a server: there is no backend and nothing is stored anywhere.

From another language#

Because the document is plain JSON with SI numbers and canonical pin names, any language can produce or edit one and hand it to the CLI. Python, for instance, can read an exported document, change a value and build the share link itself with the encoding above:

edit.pyPython
import json, zlib, base64

doc = json.load(open("led-driver.circuit.json"))
next(c for c in doc["components"] if c["id"] == "R1")["params"]["r"] = 270
json.dump(doc, open("led-driver-270.circuit.json", "w"), indent=2)
# → npx circuitsvibe verify led-driver-270.circuit.json --json   (exit 3 + T010–T014 if anything is off)

canonical = json.dumps(doc, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
raw = zlib.compressobj(wbits=-15)                       # raw DEFLATE (RFC 1951)
payload = raw.compress(canonical.encode()) + raw.flush()
link = "https://circuitsvibe.com/app.html#c=1." + base64.urlsafe_b64encode(payload).rstrip(b"=").decode()

Number formatting differs between languages (Python writes 1e-05 where JavaScript writes 0.00001), so a document produced elsewhere is an equal document with a different URL; both decode and verify identically. Check any hand-made document with npx circuitsvibe verify my.circuit.json --json, which reports T010–T014 with a JSON-pointer evidence.path.

Limitations#

What the engine does not do today. Everything else on this page is implemented and covered by the test suite and the benches in bench/.

AreaNot available
Analysesnoise, distortion and pole-zero analysis; temperature and junction self-heating; SPICE netlist import/export; a sparse linear solver (dense LU: sub-second at ~200 nodes)
SemiconductorsJFETs; MOSFET levels above 1 (Level-1 lumped gate capacitances only, no Meyer intrinsic capacitances); BJT base-resistance modulation and excess phase; Darlingtons as catalog parts (TIP120 is data only); .model cards other than D / NPN / PNP / NMOS / PMOS LEVEL=1
Op-amps, comparatorsCMRR/PSRR, input noise, input resistance/capacitance, capacitive-load interaction, phase reversal; the common-mode range is checked (R423) but not modelled; ratings are checked at the operating point only; comparators have no push-pull output, no internal hysteresis, no strobe/balance pins; dual parts are single channels
Logic ICstpd is fixed at the t = 0 supply (Rout and thresholds track it); an IC stays off after a brown-out; logic levels never change inside the AC analysis; no core supply current (Icc), ground bounce or input capacitance; 74HC74 with ~PRE and ~CLR both low gives X
Microcontrollersinstruction timing (zero time between awaits), ISR preemption, level-triggered and pin-change interrupts, UART timing and serial input from the bench, ADC conversion time, sleep modes / watchdog, core supply current, delayed power-up and restart after brown-out, pulseIn / shiftOut / Wire (I2C) / SPI / EEPROM / Wi-Fi, analogWriteFrequency / LEDC channels; --set and tb.param cannot target an MCU; the Uno board model has no regulator, USB bridge or on-board LED
VHDLwait for / wait on, while loops, functions and procedures, packages, records, arrays and memories, real / bit / character, textio, std_logic_arith; integers do not wrap (V751)
Documents and sharingdefineComponent parts and inline MCU firmware cannot be exported or shared (T013); benches carry no viewer layout

For AI agents#

CircuitsVibe is built to be driven by a coding agent. Everything an agent needs is available as text, offline and on the web:

AGENTS.md — circuitsvibe.com/AGENTS.md

The playbook: the exact loop to follow, the bench API cheat sheet, components, probes, assertions, units, every diagnostic code and the pitfalls. npx circuitsvibe init writes it next to your first bench, npx circuitsvibe agents prints it, and it is checked into the repository root.

llms.txt — circuitsvibe.com/llms.txt

The entry point for crawlers and agents: a one-paragraph description and links to the playbook, this documentation, the npm package, the standalone file and the format specifications.

Claude skill — skills/circuitsvibe/SKILL.md

The same workflow packaged as a skill (in the repository): when to use it, the loop, a minimal bench and the reference commands to run on demand.

circuitsvibe-standalone.mjs — circuitsvibe.com/circuitsvibe-standalone.mjs

The whole CLI in one zero-dependency file for sandboxes without npm: node circuitsvibe-standalone.mjs verify x.bench.ts --json. Same commands, same output.

Reference on demand

npx circuitsvibe catalog --json dumps every component and part with pins and value semantics; npx circuitsvibe explain <code> gives the physics and fixes of one diagnostic; npx circuitsvibe log list --json is the history that survives a lost context window.
