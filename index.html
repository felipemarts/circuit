The agent loop

The feedback loop that made coding agents work — now for electronics.

A bench is a test: the circuit plus its spec as assertions. verify climbs the ladder lint → op → tran and fails fast; every failure carries a stable code, the source line, and — when you delegate sizing — a hint the platform has already simulated.

Write a bench

Components with named pins, tb.param for free values, tb.expect for the spec.

Run verify

Lint checks the topology as a graph before any solver; then DC operating point; then transient.

Read the diagnostic

Stable code (A301, F105), measured vs expected, at file:line.

Apply the verified hint

The passing range was simulated, not guessed. --set R1=261.016 or edit the bench.

Green

PASS · exit 0. Deterministic output: two runs diff cleanly, so the agent sees exactly what changed.

Quick start

Up and running in an empty folder.

Nothing to install first — npx fetches the package. init scaffolds a bench and an AGENTS.md playbook; verify runs the ladder; --json returns the full RunRecord for agents.

terminalsh
$ npx circuitsvibe init my-circuit     # scaffolds my-circuit.bench.ts + AGENTS.md
$ npx circuitsvibe verify my-circuit.bench.ts
$ npx circuitsvibe verify my-circuit.bench.ts --json   # full RunRecord for agents
1
Offline or sandboxed agents: download the single zero-dependency file circuitsvibe-standalone.mjs and run node circuitsvibe-standalone.mjs verify x.bench.ts.
2
Agent playbook: point your agent at circuitsvibe.com/llms.txt, or print it locally with circuitsvibe agents. The short alias cvibe works for every command.
3
Branch on the exit code. 0 done · 1 adjust values (apply the hint) · 2 fix the structure first · 3 fix the bench or the invocation.
0all stages pass
1assertion failed — circuit valid, spec not met
2invalid or unsolvable circuit
3tooling or bench error
led-driver.bench.tsTypeScript
import { bench, VoltageSource, Resistor, LED } from 'circuitsvibe';

export default bench('led-driver', (tb) => {
  const v1 = tb.add('V1', new VoltageSource(5));
  const r1 = tb.add('R1', new Resistor('330'));
  const d1 = tb.add('D1', new LED());
  v1.pin('+').connect(r1.pin('1'));
  r1.pin('2').connect(d1.pin('anode'));
  d1.pin('cathode').connect(tb.gnd);
  v1.pin('-').connect(tb.gnd);

  tb.param('R1', { min: '100', max: '10k', scale: 'log' }); // sizing is the platform's job
  tb.expect.op('D1.i').toBeWithin('8m', '12m');             // spec as a test
});
Why it works for agents

Diagnostics you can branch on. Numbers you can trust.

Every design decision serves one metric: iterations to green. Less text to parse, fewer guesses, no silent lies.

Stable diagnostic codes

F101…T002 are permanent — never renumbered — so parsers and agents can key on them. Every one has a slug, a severity and explain docs.

Lint before the solver

Floating nets, unreached components, source loops and clamped diodes are caught on the pure graph. singular matrix never reaches you.

Simulation-verified hints

Declare tb.param('R1', …). On a failed assertion the platform sweeps the range, simulates each point and returns the range that provably passes.

Exit codes with meaning

0 pass · 1 spec not met · 2 invalid circuit · 3 tooling error. The agent decides its next move without reading prose.

Deterministic by design

No timestamps, no colors in --json; the netlist hash identifies the circuit. Two identical runs produce byte-identical records.

Runs in Node and in the browser

Same engine — Modified Nodal Analysis with Newton-Raphson — in the CLI, in a test runner and in the visual simulator.

Zero native dependencies

Pure TypeScript. npx it anywhere, or drop the single-file circuitsvibe-standalone.mjs into an air-gapped sandbox.

A run ledger

Every run is appended to .circuitsvibe/runs.jsonl. log list and log show recover what was tried after the context is gone.

Visual simulator

Watch the current move.

The same engine drives a canvas: current as glowing dots whose speed follows the current, wires colored by node voltage, an oscilloscope on probes. Each example opens in the editor — tweak values, press play.

Roadmap

What exists today, and what is coming.

Today: DC operating point and transient analysis, nine built-in parts plus defineComponent, the lint → op → tran ladder, stable diagnostics with verified hints, the CLI with --json and a run ledger, and the visual simulator.

Planned — not implemented yet. Nothing below exists in the CLI or in the app today; the docs only describe shipped features.
coming

DC sweep and AC analysis

Transfer curves, Bode plots, bandwidth and phase margin as assertable quantities.

coming

Adaptive transient + sources

coming

Transistors and a real-parts catalog

BJTs and MOSFETs (2N3904, BC547B, 2N7000, IRLZ44N…), 1N4148/1N4007/1N4733A, with datasheet ratings checked automatically.

coming

Op-amps and comparators

coming

coming

RunRecord viewer in the app

Assertion results and hints rendered on the schematic and the oscilloscope.
