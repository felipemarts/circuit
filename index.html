prompt for your agenttext
You can design and simulate electronic circuits with CircuitsVibe, a circuit simulator built for AI agents. It runs locally with Node ≥ 20 through npx; there is nothing to install.

1. Before anything else, run `npx circuitsvibe agents` and read the whole playbook it prints: bench API, components, assertions, diagnostic codes and pitfalls. Follow it exactly. If you cannot run commands, read https://circuitsvibe.com/AGENTS.md instead.
2. For each circuit I ask for, write a bench `<name>.bench.ts` (start with `npx circuitsvibe init <name>`): the circuit, its free parameters (`tb.param`) and my requirements as assertions (`tb.expect.*`). When I name a real part, use `Part('<id>')` and check `npx circuitsvibe catalog <id>` for its pins and ratings.
3. Run `npx circuitsvibe verify <name>.bench.ts --json` and decide only from the exit code:
   - 0: done, every stage passed.
   - 1: the circuit is valid but a requirement or a part rating failed. If the failed assertion has a hint with kind "verified-param-range", re-run with `--set <id>=<hint.suggestedValue>`; otherwise change values or topology.
   - 2: the circuit is invalid or unsolvable. Fix the structure at `diagnostics[].at` before touching values.
   - 3: the bench threw or the command was wrong. Fix the code or the invocation.
   Run `npx circuitsvibe explain <code>` for any diagnostic you don't understand, and check `npx circuitsvibe log list --json` before each retry so you never repeat a configuration that already failed.
4. Never invent component values or measurements. Let `tb.param` find the passing range, and only quote numbers that come from the RunRecord.
5. When verify exits 0, write the passing values back into the bench, run `npx circuitsvibe share <name>.bench.ts` and give me the link it prints, with a short summary of what was verified and the measured values.

If npx has no network access, download https://circuitsvibe.com/circuitsvibe-standalone.mjs and run `node circuitsvibe-standalone.mjs <command>` instead.

The agent loop

The feedback loop that made coding agents work — now for electronics.

A bench is a test: the circuit plus its spec as assertions. verify climbs the ladder lint → op → dc → ac → tran and fails fast; every failure carries a stable code, the source line, and — when you delegate sizing — a hint the platform has already simulated. The loop in the docs →

Write a bench

Components with named pins — resistors, Part('2N3904'), a 74HC04, a VHDL block, an Arduino with its firmware — tb.param for free values, tb.expect for the spec.

Run verify

Lint checks the topology as a graph before any solver; then the operating point, the DC sweep, AC and the transient — logic, VHDL and firmware co-simulated in lockstep.

Read the diagnostic

Stable code (A301, F105, R402), measured vs expected, at file:line — the firmware or .vhd line when that is where the fault is.

Apply the verified hint

The passing range was simulated, not guessed — datasheet ratings included. --set R1=261.016 or edit the bench.

Green, then share

PASS · exit 0. Deterministic output: two runs diff cleanly. share gives a link that re-runs the bench in the browser with the same verdict.

Quick start

Up and running in an empty folder.

Nothing to install first — npx fetches the package. init scaffolds a bench and an AGENTS.md playbook; verify runs the ladder; --json returns the full RunRecord for agents.

terminalsh
$ npx circuitsvibe init my-circuit     # scaffolds my-circuit.bench.ts + AGENTS.md
$ npx circuitsvibe verify my-circuit.bench.ts
$ npx circuitsvibe verify my-circuit.bench.ts --json   # full RunRecord for agents
1
Offline or sandboxed agents: download the single zero-dependency file circuitsvibe-standalone.mjs and run node circuitsvibe-standalone.mjs verify x.bench.ts.
2
Agent playbook: point your agent at circuitsvibe.com/llms.txt, or print it locally with circuitsvibe agents. The short alias cvibe works for every command.
3
Branch on the exit code. 0 done · 1 adjust values (apply the hint) · 2 fix the structure first · 3 fix the bench or the invocation.
0all stages pass
1assertion failed — circuit valid, spec not met
2invalid or unsolvable circuit
3tooling or bench error
led-driver.bench.tsTypeScript
import { bench, VoltageSource, Resistor, LED } from 'circuitsvibe';

export default bench('led-driver', (tb) => {
  const v1 = tb.add('V1', new VoltageSource(5));
  const r1 = tb.add('R1', new Resistor('330'));
  const d1 = tb.add('D1', new LED());
  v1.pin('+').connect(r1.pin('1'));
  r1.pin('2').connect(d1.pin('anode'));
  d1.pin('cathode').connect(tb.gnd);
  v1.pin('-').connect(tb.gnd);

  tb.param('R1', { min: '100', max: '10k', scale: 'log' }); // sizing is the platform's job
  tb.expect.op('D1.i').toBeWithin('8m', '12m');             // spec as a test
});
What it does

Diagnostics you can branch on. Numbers you can trust.

One engine from a resistor to an Arduino running your firmware. Every design decision serves one metric: iterations to green — less text to parse, fewer guesses, no silent lies.

The whole analog ladder

DC operating point, DC sweep (transfer curves, slopes, crossings), AC (gain, phase, −3 dB bandwidth, phase margin) and an adaptive transient with PULSE, PWL, PWM and SIN sources. Each stage fails fast with a stable code.

Real parts, datasheet ratings

Part('2N3904'), IRLZ44N, 1N4733A, LM358, LM393… come with the catalog model and the absolute maximum ratings. Voltage, current, pulsed current and power are checked after every stage (R401–R404, R420–R425) — a violation is exit 1 with the datasheet citation.

Mixed-signal, VHDL and firmware

74HC / CD4000 ICs and the NE555 with datasheet levels and delays, VHDL blocks on the event engine, and an Arduino Uno running TypeScript firmware in lockstep with the transient — pins, ADC, PWM, interrupts, Serial. Logic analyzer and serial assertions in the same run.

Share links that re-simulate

circuitsvibe share puts the whole circuit — firmware and .vhd included — in a URL. The viewer draws the schematic and runs the very same engine in the browser: same verdict, exit code and netlist hash as your CLI run. Logged in, it gets a short link instead: private for 24 h, or public on the wall.

Stable diagnostic codes

F1xx lint, S2xx solver, A301 assertions, R4xx ratings, D5xx digital, M6xx firmware, V7xx VHDL — permanent, never renumbered, each with at file:line and explain docs.

Lint before the solver

Floating nets, source loops, clamped diodes, a base without a resistor, an unpowered IC, a floating gate input — caught on the pure graph with a fix attached. singular matrix never reaches you.

Verified hints, exit codes with meaning

Declare tb.param('R1', …): on a failed assertion the platform sweeps the range, simulates each point and returns the range that provably passes — ratings included. 0 pass · 1 spec not met · 2 invalid circuit · 3 tooling error.

Deterministic, with a ledger

No timestamps in --json; the netlist hash identifies the circuit and two identical runs produce byte-identical records. Every run is appended to .circuitsvibe/runs.jsonl, so log list recovers what was tried after the context is gone.

FAQ

Questions about vibe hardware

What is vibe hardware?

Designing electronics by describing what you want to an AI agent, the way vibe coding works for software. Hardware needs proof before you solder, so CircuitsVibe gives the agent a circuit simulator with exit codes: the circuit is checked by simulation before it reaches you.

Which AI agents can use it?

Any agent that can run terminal commands, such as Claude Code, OpenAI Codex, Cursor, Gemini CLI or GitHub Copilot in agent mode. It needs Node.js 20 or newer. Chat-only assistants can read llms.txt and write the bench for you to run.

What can it simulate?

DC operating point, DC sweep, AC (Bode) and transient. Resistors, capacitors, inductors, sources, diodes, Zeners, LEDs, BJTs, MOSFETs, op-amps and comparators, 74HC and CD4000 logic, the NE555, VHDL blocks, and an Arduino Uno, ATtiny85, ESP32 or RP2040 running TypeScript firmware. Real catalog parts are checked against their datasheet ratings.

Is my circuit uploaded anywhere?

Only if you choose to. The simulation always runs on your machine. Without an account, a share link carries the compressed circuit in the URL fragment, which browsers never send to the server. If you log in, share stores the circuit in the CircuitsVibe circuit cache behind a short link: private links expire after 24 hours, public ones go to the wall.

Can it design the PCB too?

Yes. Declare the board (tb.board) and place the parts (tb.place): the pcb stage picks the footprints, checks the placement, autoroutes on one or two layers with traces sized from the simulated current, and checks the design rules. Gerber, drill, BOM and pick-and-place export and a 3D view are next on the roadmap.

Is it free?

Yes. CircuitsVibe is open source under the MIT license and installs from npm as circuitsvibe.

How does it compare to SPICE?

It uses the same numerical methods (modified nodal analysis, Newton-Raphson, trapezoidal integration, SPICE-style device models and .model cards) but is built for agents: specs as assertions, exit codes, stable diagnostic codes with file:line, simulation-verified sizing hints and deterministic JSON. It does not do noise analysis, temperature effects or MOSFET levels above 1.
