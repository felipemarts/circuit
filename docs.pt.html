Início rápido#

O CircuitsVibe é um simulador de circuitos analógicos que você dirige por código — o vitest dos circuitos. Você descreve um circuito e sua especificação numa bancada em TypeScript; o verify simula com um motor de Análise Nodal Modificada (Newton-Raphson para peças não lineares) e responde com um veredito, um código de saída e diagnósticos que carregam um código estável, a localização no fonte e — sempre que possível — uma correção que a plataforma já simulou. O mesmo motor roda em Node e no navegador, sem dependências nativas.

Sem instalar nada, numa pasta vazia#

terminalsh
$ npx circuitsvibe init my-circuit     # cria my-circuit.bench.ts + AGENTS.md
$ npx circuitsvibe verify my-circuit.bench.ts
$ npx circuitsvibe verify my-circuit.bench.ts --json   # RunRecord completo para agentes
  • init [nome] escreve <nome>.bench.ts (um driver de LED que passa como está) e um playbook AGENTS.md para o seu agente de código.
  • verify roda a escada lint → op → tran e sai com 0, 1, 2 ou 3 (veja códigos de saída).
  • O alias curto cvibe aceita todos os comandos: npx cvibe verify ….

Agentes offline ou em sandbox#

Quando o agente não alcança o npm, baixe um único arquivo sem dependências e rode com Node:

standalonesh
$ curl -O https://circuitsvibe.com/circuitsvibe-standalone.mjs
$ node circuitsvibe-standalone.mjs verify x.bench.ts

O playbook do agente também está publicado em circuitsvibe.com/llms.txt; circuitsvibe agents imprime o mesmo AGENTS.md localmente.

Sua primeira bancada#

led-driver.bench.tsTypeScript
import { bench, VoltageSource, Resistor, LED } from 'circuitsvibe';

export default bench('led-driver', (tb) => {
  const v1 = tb.add('V1', new VoltageSource(5));
  const r1 = tb.add('R1', new Resistor('330'));
  const d1 = tb.add('D1', new LED());
  v1.pin('+').connect(r1.pin('1'));
  r1.pin('2').connect(d1.pin('anode'));
  d1.pin('cathode').connect(tb.gnd);
  v1.pin('-').connect(tb.gnd);

  tb.param('R1', { min: '100', max: '10k', scale: 'log' }); // sizing is the platform's job
  tb.expect.op('D1.i').toBeWithin('8m', '12m');             // spec as a test
});

Três ideias em catorze linhas: componentes têm ids estáveis ('R1'), pinos têm nomes ('anode', '+') e a especificação é uma asserção sobre uma sonda. tb.param entrega o valor do resistor à plataforma — se a asserção falhar, você recebe uma faixa verificada que passa, em vez de um chute.

O loop do agente#

Um agente LLM itera sobre um circuito do mesmo jeito que itera sobre código com um test runner:

  1. Escreve (ou edita) a bancada.
  2. Roda circuitsvibe verify x.bench.ts --json.
  3. Decide pelo código de saída. 0 → pronto. 1 → o circuito é válido mas a spec não foi atendida: ajuste valores, de preferência aplicando o hint. 2 → o circuito é estruturalmente inválido ou insolúvel: corrija a topologia primeiro. 3 → a própria bancada ou a invocação está quebrada.
  4. Lê o diagnóstico: o code é estável, o at aponta para a linha problemática e toda correção carrega um rótulo de confiança.
  5. Aplica a correção e volta ao passo 2.

A escada é fail-fast: o lint roda sobre o grafo de conexões antes de qualquer solver, o op resolve o ponto de operação DC, o tran roda o transitório. Quando uma etapa falha, as seguintes aparecem como skipped — o agente nunca precisa decidir qual de vários erros é a causa raiz.

API de bancada#

Um arquivo de bancada exporta por padrão bench(name, build). A função build é preguiçosa: roda na elaboração, possivelmente várias vezes com overrides diferentes (--set, micro-varreduras), então mantenha-a pura — construa o circuito a partir dos argumentos e de nada mais.

bench(name: string, build: (tb) => void)

Declara uma bancada. name aparece em todo relatório e RunRecord.

tb.add(id: string, component: T): T

Registra um componente sob um id estável (letras, dígitos, underscore, começando com letra — ex.: 'R1'). O id é como sondas, diagnósticos e --set se referem a ele. Os ids devem ser únicos e cada instância só pode ser registrada uma vez.

Use sempre o valor retornado. Quando há um override ativo para aquele id, add devolve uma instância reconstruída; conectar pinos no original ligaria silenciosamente a peça errada (a plataforma recusa pinos conectados antes do add).

tb.gnd: Pin

O pino de terra. Todo nó precisa de um caminho DC até ele (veja F101).

tb.name(netName: string, pin: Pin)

Dá nome ao nó elétrico que contém pin, para que ele possa ser sondado em asserções op (tb.expect.op('out')). 'gnd' e os nomes automáticos (n1, n2, …) são reservados.

tb.param(id, { min, max, scale?: 'lin' | 'log' })

Declara um parâmetro livre sobre o valor escalar de um componente — veja Dimensionar com tb.param. min < max; 'log' exige min > 0. Só Resistor, Capacitor, Inductor, VoltageSource e CurrentSource têm valor varrível.

tb.expect.op(probe) · tb.expect.tran({ tstop, dt })

Asserções — a especificação como teste. Veja Sondas e asserções e Medições transitórias.

Todo componente ligado precisa estar registrado. Uma peça conectada ao circuito mas nunca passada por tb.add é um erro de elaboração (exit 3): a netlist, o hash e o lint precisam ver tudo o que o solver vê.

Valores e unidades#

Onde um valor é esperado você pode passar um número ou uma string com sufixo de engenharia: '4.7k', '10m', '2u', '1M', '1e-6'.

m ≠ M. m é mili (10⁻³) e M é mega (10⁶): '10m' são 10 mΩ / 10 mA / 10 ms; '1M' é 1 MΩ.

Sondas e asserções#

Toda asserção mede uma sonda. A gramática tem três regras:

SondaMedeExemploEtapas
'<id>.i'corrente através do componente'D1.i'op, tran
'<id>.v'tensão sobre o componente'R1.v'op, tran
'<net>'tensão de um nó nomeado com tb.name'out'só op

Nomes automáticos de nó (n1, n2, …) são deliberadamente inacessíveis: nomeie os nós que importam com tb.name('out', pin) para que as sondas continuem estáveis entre edições.

op — ponto de operação DC#

asserções opTypeScript
tb.name('out', r1.pin('2'));

tb.expect.op('D1.i').toBeWithin('8m', '12m');   // min ≤ medido ≤ max
tb.expect.op('out').toBeCloseTo(3.3, 0.1);      // |medido − valor| ≤ tol
tb.expect.op('R1.v').toBeAbove('1.5');          // medido > valor
tb.expect.op('R1.v').toBeBelow(4);              // medido < valor

Os matchers devolvem a expectativa, então encadeiam. Cada chamada registra uma asserção (a1, a2, … na ordem do relatório) com a localização da chamada no fonte.

Medições transitórias#

tb.expect.tran({ tstop, dt }) declara uma execução transitória — passo fixo dt até tstop (no máximo 5.000.000 passos) — e .probe(p) escolhe uma grandeza de componente ('C1.v', 'D1.i'; nós nomeados são só para op). Os matchers encadeiam, e .probe() pode ser chamado de novo para afirmar sobre outra sonda da mesma execução.

asserções tranTypeScript
tb.expect.tran({ tstop: '5m', dt: '1u' })
  .probe('C1.v')
  .toSettleWithin({ target: 5, tol: 0.02, by: '4m' }) // dentro de 5 V ± 2 % a partir de 4 ms
  .toNeverExceed(5.5)                                  // sem overshoot acima de 5,5 V
  .probe('R1.i')
  .toStayBelow('6m', { from: '1m' });                  // depois de 1 ms, corrente < 6 mA
MatcherPassa quando
toSettleWithin({ target, tol, by })de t = by até o fim, o sinal fica dentro de target ± tol·|target|. target deve ser não nulo e by ≤ tstop.
toNeverExceed(v)o sinal nunca ultrapassa v em nenhuma amostra.
toStayAbove(v, { from })para t ≥ from (padrão: a execução inteira) o sinal fica acima de v.
toStayBelow(v, { from })para t ≥ from o sinal fica abaixo de v.
toRippleBelow(amp, { from })o ripple pico a pico em t ≥ from (padrão tstop/2) fica abaixo de amp.
toEndCloseTo(v, tol)a última amostra está a até tol de v.

Uma asserção tran que falha reporta measured, o instante da primeira violação e um pequeno trecho da forma de onda ao redor dela no RunRecord. Um settleWithin que nunca estabiliza reporta o valor do fim da janela — sempre um número finito, nunca Infinity.

Para um estímulo senoidal, defina v1.acAmplitude e v1.frequency numa VoltageSource (o valor DC é o offset). Fontes PULSE/PWL/PWM e passo adaptativo estão no roadmap.

Dimensionar com tb.param#

Modelos de linguagem são bons em topologia e ruins em dimensionamento contínuo. tb.param delega o número: declare a faixa que um valor pode assumir e, quando uma asserção op falha, a plataforma varre essa faixa (linear ou log), simula cada amostra e devolve a faixa contígua em que o lint e todas as asserções op passam.

delegando R1TypeScript
tb.param('R1', { min: '100', max: '10k', scale: 'log' });
tb.expect.op('D1.i').toBeWithin('8m', '12m');

Na falha, a asserção carrega um hint:

assertion.hintJSON
{
  "kind": "verified-param-range",
  "param": "R1",
  "passingRange": [261.016, 316.228],
  "suggestedValue": 261.016,
  "passingSamples": [261, 316.2],
  "note": "log sweep; every listed value passes ALL op assertions (simulated)"
}
  • passingRange cobre apenas a sequência contígua mais longa de amostras que passam; os valores exatos simulados estão em passingSamples.
  • Aplique sem tocar no arquivo — verify x.bench.ts --set R1=261.016 — ou edite a bancada. --set aceita vários ids: --set R1=280,V1=5.
  • Nenhum hint no registro significa que nenhum valor da faixa declarada satisfaz a spec: mude a topologia, não o número.
  • --no-hints pula a varredura quando você só quer o veredito.

Diagnósticos#

Os códigos são permanentes: nunca são renumerados nem reescritos, então parsers e agentes podem depender deles. circuitsvibe explain <código> imprime a explicação longa com a física por trás de cada um.

T0xxferramentaerro de autoria da bancada / da plataforma

Confiança das correções#

Toda correção num diagnóstico ou hint carrega um rótulo confidence:

verified

A plataforma simulou a correção e ela passa em todas as asserções da etapa. Aplique diretamente.

mechanical

Uma transformação determinística — não simulada, mas sem exigir julgamento.

suggested

Uma heurística. Raciocine antes de aplicar.

Dois invariantes valem: uma correção nunca referencia uma flag ou capacidade que não existe, e um número não simulado nunca é emitido sem o rótulo suggested.

Códigos de saída#

CódigoSignificadoAção do agente
0todas as etapas pedidas passampronto
1asserção falhou — circuito válido, spec não atendidaajustar valores (aplicar o hint) ou a topologia
2circuito inválido ou insolúvel (erro F/S)corrigir a estrutura primeiro
3erro de ferramenta — uso incorreto, a bancada lançou erro, ou T002corrigir a bancada ou a invocação
  • O lint sempre roda, mesmo com --stage op: resolver um circuito que o lint rejeitaria significaria descartar componentes em silêncio e reportar números inventados.
  • firstFailure no RunRecord é o id da asserção ou o código do diagnóstico que decidiu o veredito.

Referência da CLI#

O binário é circuitsvibe; cvibe é um alias curto. A saída é determinística — sem timestamps, sem cores no texto — então duas execuções idênticas dão um diff limpo.

comandos
circuitsvibe init [nome]                     cria <nome>.bench.ts + AGENTS.md (padrão: my-circuit)
circuitsvibe verify <bench.ts> [opções]      roda a escada: lint → op → tran
circuitsvibe log list [--json]              lista execuções passadas do histórico (.circuitsvibe/runs.jsonl)
circuitsvibe log show <runId>               RunRecord completo de uma execução passada
circuitsvibe explain <código>               explicação longa de um diagnóstico, ex.: explain F105
circuitsvibe catalog [tipo] [--json]        datasheet dos componentes + gramática de sondas/asserções
circuitsvibe agents                         imprime o playbook do agente (AGENTS.md)

opções do verify
  --json                 emite o RunRecord completo em JSON no stdout
  --set R1=280,V1=5      sobrescreve valores escalares sem editar a bancada
  --stage op,tran        roda só essas etapas (o lint SEMPRE roda)
  --no-hints             pula os hints verificados de dimensionamento (mais rápido)
  --no-ledger            não anexa esta execução a .circuitsvibe/runs.jsonl

Invocação típica de um agente#

terminalsh
$ npx circuitsvibe verify my-circuit.bench.ts --json > run.json
$ echo $?   # 0 passou · 1 asserção falhou · 2 circuito inválido · 3 erro de ferramenta
$ npx circuitsvibe log list   # o que já foi tentado, depois que o contexto se foi

O histórico anexa um registro por execução em .circuitsvibe/runs.jsonl no diretório de trabalho; log show <runId> reproduz qualquer um deles por completo.

Componentes customizados#

defineComponent cria um tipo de componente a partir de um objeto de definição. A peça se estampa na matriz MNA por um pequeno contexto, pode manter estado interno entre passos transitórios e roda no mesmo motor das peças nativas — em bancadas e no simulador visual.

defineComponent({ name, pins, params?, stamp, setup?, onStep?, nonlinear?, draw?, label?, pinLayout? })

Devolve um construtor: new MinhaPeca({ nomeDoParametro: valor }). pins é a lista de nomes de pino; params mapeia um nome para { default, unit? }.

stamp(ctx)

Chamado a cada resolução. Use ctx.stampResistance(p1, p2, R), ctx.stampConductance(p1, p2, g), ctx.stampCurrentSource(pMais, pMenos, i), ctx.stampVoltageSource(pMais, pMenos, vsIdx, v); leia ctx.params, ctx.state, ctx.time, ctx.dt e a última solução com ctx.voltage(pin).

setup(state) · onStep(ctx, dt) · nonlinear

setup inicializa state uma vez; onStep roda antes de stamp a cada passo transitório. Defina nonlinear: true quando a estampa depender das tensões de nó, para que o Newton-Raphson itere.

draw(ctx2d, w, h) · label · pinLayout

Só para o simulador visual: um símbolo customizado no canvas, o prefixo do rótulo (padrão: as três primeiras letras de name) e os deslocamentos por pino { dx, dy }.

Um microcontrolador com dois GPIOs#

Este é o componente por trás do exemplo MCU + LEDs: cada GPIO é um equivalente de Norton (Vcc através de Rout) chaveado por um pequeno "programa" em onStep.

components.jsJavaScript
const MCU = defineComponent({
  name: 'MCU',
  pins: ['gnd', 'gpio0', 'gpio1'],
  params: {
    Vcc: { default: 5, unit: 'V' },
    Rout: { default: 100, unit: 'Ohm' },
  },
  nonlinear: true,
  setup(state) {
    state.gpio0 = 0;
    state.gpio1 = 0;
  },
  onStep(ctx) {
    // Programa: alterna os LEDs a cada 1 ms
    const period = 0.002;
    const phase = (ctx.time % period) / period;
    ctx.state.gpio0 = phase < 0.5 ? 1 : 0;
    ctx.state.gpio1 = phase >= 0.5 ? 1 : 0;
  },
  stamp({ stampConductance, stampCurrentSource, params, state }) {
    const G = 1 / params.Rout;
    stampConductance('gpio0', 'gnd', G);
    if (state.gpio0) stampCurrentSource('gpio0', 'gnd', params.Vcc * G);
    stampConductance('gpio1', 'gnd', G);
    if (state.gpio1) stampCurrentSource('gpio1', 'gnd', params.Vcc * G);
  },
});

Numa bancada, registre como qualquer outra peça — tb.add('U1', new MCU()) — e ligue os pinos pelo nome. Os params numéricos entram na netlist canônica, então duas peças customizadas eletricamente diferentes nunca compartilham um hash. Peças customizadas não têm escalar varrível, então tb.param e --set não se aplicam a elas.

Usando o simulador visual#

O simulador roda o mesmo motor no seu navegador, 100 % local. Ele tem duas superfícies que ficam em sincronia: um canvas com paleta de peças e um editor de código cujo script constrói o circuito. O canvas é uma projeção do código; Gerar código faz o caminho inverso.

API de script no editor#

O editor expõe Circuit, Ground, Junction, as nove peças nativas, defineComponent e console. Valores aceitam números ou strings com unidade.

main.js — no simuladorJavaScript
const circuit = new Circuit();
const gnd = new Ground();

const v1 = new VoltageSource(5);
const r1 = new Resistor(1000);
const c1 = new Capacitor('1u');

v1.pin('+').connect(r1.pin('1'));
r1.pin('2').connect(c1.pin('1'));
c1.pin('2').connect(gnd.pin('1'));
v1.pin('-').connect(gnd.pin('1'));

circuit.probe(c1, 'voltage');                 // 'voltage' | 'current', rótulo e cor opcionais
const result = circuit.analyze('transient', { timeStep: 1e-5, duration: 5e-3 });

const curve = result.probes[0].values;        // result.timePoints guarda o eixo do tempo
console.log('Vc após 5τ:', curve[curve.length - 1].toFixed(3), 'V');
console.log('Corrente em R1:', (r1.current * 1000).toFixed(3), 'mA'); // comp.voltage / comp.current
  • circuit.analyze('dc') resolve o ponto de operação; depois disso cada componente expõe .voltage e .current.
  • circuit.analyze('transient', { timeStep, duration }) precisa de pelo menos um circuit.probe(...); devolve { timePoints, probes: [{ label, color, values }] } e abre a aba Gráfico.
  • Arquivos: o editor tem abas (+ adiciona uma, duplo clique renomeia); todos os arquivos são concatenados antes de rodar. Ctrl+Enter executa.

Canvas e simulação ao vivo#

  • Paleta à esquerda: clique numa ferramenta, clique no canvas para posicionar. R gira a seleção, Delete remove, Esc volta para selecionar. Os fios se roteiam sozinhos ao redor das peças; arraste um fio para fixar seu trecho do meio.
  • Play (Espaço) inicia um transitório contínuo. O controle Tempo define segundos simulados por segundo real. Clique numa Chave ou segure um Botão enquanto roda.
  • Corrente aparece como pontos luminosos percorrendo os fios — a velocidade acompanha a corrente. Os fios são coloridos pela tensão do nó (legenda no canto), as peças brilham quando ativas e o brilho de um LED acompanha sua corrente.
  • Sondas: escolha a ferramenta de sonda e clique num pino; o osciloscópio sobreposto mostra os traços com máx / mín / faixa / frequência / RMS, e a aba Gráfico guarda a forma de onda completa.
  • Projetos ficam salvos no seu navegador (Projeto → Salvar), são exportados e importados como JSON, e o trabalho em andamento é salvo automaticamente.
